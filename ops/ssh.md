# SSH access

Forge uses two separate SSH boundaries:

| Port | User | Purpose | Credential boundary |
| --- | --- | --- | --- |
| `22` | `operator` | NixOS administration | Public keys installed by the host bootstrap or provider recovery path |
| `2222` | `git` | Forgejo repository clone and push | Forgejo account SSH keys |

Forgejo's built-in SSH server owns port `2222`. Keeping it separate from
OpenSSH prevents repository keys from becoming operating-system login keys and
leaves operator access independently recoverable. The built-in listener is
unprivileged and must not be changed to port 22.

## Local VM

The local QEMU target forwards host `127.0.0.1:2222` to the Forgejo Git SSH
listener and host `127.0.0.1:2200` to guest OpenSSH. The disposable local
operator account is `operator` / `forge-local-operator`; use it only to inspect
the VM console and service logs:

```sh
ssh -p 2200 operator@127.0.0.1
```

Add an SSH key to the test account in Forgejo, then verify a remote without
using an HTTP password:

```sh
ssh-keygen -t ed25519 -f ~/.ssh/forge-local-git -C forge-local-git
GIT_SSH_COMMAND='ssh -F /dev/null -i ~/.ssh/forge-local-git -o IdentitiesOnly=yes -o StrictHostKeyChecking=no -o UserKnownHostsFile=/dev/null -o ConnectTimeout=10' \
  git ls-remote ssh://git@127.0.0.1:2222/OWNER/REPOSITORY.git
```

The local fixture uses deterministic disposable administrator passwords so a
fresh VM can be audited repeatedly:

- Forgejo: `forge-admin@forge.localhost` / `forge-local-forgejo-admin`
- Discourse: `admin@discourse.local` / `forge-local-discourse-admin`

These values are for the disposable local target only. No operator SSH key or
production password is generated by the flake.

## Production

The Hetzner firewall allows operator SSH on `22` and Forgejo Git SSH on `2222`.
OpenSSH remains key-only and root login remains disabled. NixOS declares the
`operator` account and uses a root-owned `AuthorizedKeysCommand` to read
`/etc/forge/ssh/operator_authorized_keys` at authentication time. The Hetzner
image or bootstrap process must install that file before the first activation:

```sh
install -d -m 0700 /etc/forge/ssh
install -o root -g root -m 0600 operator_authorized_keys /etc/forge/ssh/operator_authorized_keys
```

The file contains public keys only; the corresponding private key must stay
outside this repository. Replacing the file is picked up on the next login;
verify a new key before removing an old one. Until the NetBird break-glass path
has been exercised, retain provider-console recovery and restrict port 22 at
the Hetzner firewall to the operator's source network when the deployment
workflow supports it.

Production Forgejo and Discourse administrator passwords are read from SOPS
runtime files for the one-time bootstrap units. They must be generated and
stored through the production secret workflow, not copied from the local
fixture or derived from a repository constant. After first login, rotate or
replace the bootstrap credentials during the documented break-glass review.

## Recovery and rollback

Before changing either listener or its firewall rule, keep a provider-console
session open and verify an existing operator key. If the operator key is lost,
use the provider console to restore `/etc/forge/ssh/operator_authorized_keys`
before restarting or reloading `sshd`. If Forgejo Git SSH fails,
repository access can temporarily use HTTPS while port `2222` is restored;
never remove port 22 and 2222 in the same change. If an administrator bootstrap
fails, inspect the unit and SOPS installation first. The bootstrap unit uses a
persistent marker and does not reset an existing administrator password.
